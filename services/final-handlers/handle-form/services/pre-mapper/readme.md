Данный сервис предназначен для обработки данных формы.
Сервис принимает плоские данные, и создает иерархическую структуру в соответствии со схемой переданной в method process в качестве прямого аргумента.

PreMapper я вляется звеном одной цепи где одну из важных ролей играет кастомный DSL "multitable".

Данные полученые от multitable парсера выглядят следующим образом:

## Пример работы

**Вход (из multipart-парсера):**

```js

{
  body: Buffer,
  filename: 'photo.jpg',
  contentType: 'image/jpeg',
  tableId: '25',
  groupId: 'abc123',
  columnName: 'avatar'
}

```

Выход (для PostMapper):

```js
{
  '25': {           // таблица files
    'abc123': {     // группа
      originalFileName: { action: 'data', payload: 'photo.jpg' },
      mime: { action: 'data', payload: 'image/jpeg' },
      fileSystemFileName: { action: 'file', payload: <Buffer> }
    }
  }
}

```

## Зачем нужен PreMapper

PreMapper решает проблему несоответствия между плоской структурой данных из HTML-формы и иерархической структурой, которая нужна для сохранения в базу данных.

HTML-форма отправляет плоский список полей: `[{name: "title", value: "Foo"}, {name: "video", file: ...}]`. Но база данных ожидает иерархию: `{ "video-playlist": { "01": { "title": "Foo", "video": "ссылка на файл" } } }`.

PreMapper превращает первое во второе. Это позволяет разработчику описывать сложные связи между таблицами прямо в HTML-разметке, не writing boilerplate code для каждого эндпоинта.

схема которую использует premapper выглядит следующим образом:

```js
const FileDataSetSchema = {
    /**
     * если  строка свойства начинается с "__", значит,
     * в результате работы PreMapper.process, данные будут взяты из
     * dataSet[tableId], т.е. в результирующей сруктуре будет
     *
     * "25":{ // __tableId
     *  type:'branch',
     *  value: {
     *   "00": { // __groupId
     *    ...
     *  }
     * }
     *
     */
    __tableId: {
        type: 'branch', // эта строка указывает preMapper относиться ко значению в св-ве value как вложенной структуре
        value: {
            __groupId: {
                type: 'branch',
                value: {
                    fileSystemFileName: {
                        // type: 'leaf', означает взять данные из value
                        // заменить значение с префиксом "__", на значение из dataSet, и записать в проперти результирующего объекта
                        type: 'leaf',
                        value: {
                            action: 'file',
                            payload: '__body',
                        },
                    },
                    mime: {
                        type: 'leaf',
                        value: {
                            action: 'data',
                            // здесь, данные будут так-же взяты из dataSet
                            payload: '__contentType',
                        },
                    },
                    originalFileName: {
                        type: 'leaf',
                        value: {
                            action: 'data',
                            payload: '__fileName',
                        },
                    },
                },
            },
        },
    },
};
```

premapper использует рекурсивный подход.
всегда используется схема для создания структуры.

premapper всегда ожидает структуру ввиде объекта с неограниченным колличеством свойств.

при этом имена свойств могут быть как скаляром, так и ссылкой на данные из входящего дата-сет объекта. тип (скаляр/ссылка) определяется префиксом "\_\_" или его отсутствием.

имена свойств в схеме соответствуют именам свойств в результируещей структуре.

имена свойств, вложенное значение свойства type которых содержит строку 'branch', не будут перезаписаны. вместо этого во вложенной структуре PreMapper попытается добавить новое свойство, либо перезаписать уже существующее (если оно Leaf)

теперь, имена свойств, type которых содержит строку "leaf", будут перезаписаны в соответствии с логикой PreMapper
(сейчас уже ведется разработки фич среди которых - опциональность и расширение PreMapper, где можно задавать конфигурацию в том числе и для того что бы PreMapper перезаписывал или не перезаписывал дублирующие св-ва)

каждое св-во схемы имеет следующую структуру,-
св-во:консистентное значение, где консистентное значение предполагает то что в любом ключевом свойстве данные должны содержать {type, value}
при этом, если type==='branch', то value- это вложенная структура (рекурсивный случай) типа `{propertyName:{type:string;value:Object}}`, если type === 'leaf', то это "базовый случай" и структура `{action:string;payload:any}`.

при каждом выполнении метода process premapper Ожидает схему, dataset и контекст для мутации в соответствии со схемой.

premapper для итерации по полям использует цикл for-of.
На каждой итерации он заходит в каждое свойство и динамически меняет его (или оставляет как есть) на значение из дата-сет.

на каждой итерации premapper пробует создать новое свойство или обновить существующее.

при этом на каждой итерации может быть два кейса, - "branch" или "leaf".

# case 'branch':

(рекурсивный случай)

## в объекте контекста в его корне не существует св-ва имя которого полученое в текущей итерации цикла for-of

в контексте создается новое св-во с этим именем а значение является результатом рекурсивного выполнения premapper

аргументы: propertyName.value, sameDataSet, {}

пустой объект в аргументах означает что следующий рекурсивный уровень собирается снуля.

## в объекте контекста уже существует свойство с таким именем

предполагается что значения ключевых свойств являются консистентными объектами.

аргументы для рекурсии: propertyName.value, sameDataSet, currentContext\[propertyName\]

результат выполнения должен быть проитерирован где результат каждой итерации должен разложен на ключ и значение `for (const [k,v] of Object.entries(RecursiveProcessResult))` и currentContext\[propertyName\]\[k\] = v

# case Leaf

свойство с именем полученым в текущей итерации в текущем контексте будет overrided. Значение свойства будет {action:'file'|'data'|'link';payload:'\_\_path' | 'concreteData'}
